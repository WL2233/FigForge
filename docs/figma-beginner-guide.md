# Figma 插件使用教程（小白版）

这篇教程带你把 Figma 里的界面导出成 ZIP，再交给 Unity 插件生成界面预制体。你不需要写代码，也不需要手动整理每一张图片。

本文按当前项目 1.0.59 的界面和源码编写。第一次先导出一个简单页面，成功后再批量导出。

## 1. 先认识三个东西

| 名称 | 你可以这样理解 |
| --- | --- |
| Frame（画框） | 一个完整界面的外框，例如“背包”页面 |
| 图层 | 页面里的文字、图片、按钮外观和容器 |
| ZIP 导出包 | 包含界面结构和图片的压缩文件，供 Unity 插件读取 |

整个流程：**安装插件 → 选择界面 → Add → 导出 ZIP → 在 Unity 导入**。

## 2. 安装 Figma 插件

准备 Figma 桌面客户端、可以编辑的设计文件，以及已打包的 Figma 插件。

1. 找到项目 `dist` 目录里的 `figforge-plugin-1.0.59.zip`。以后版本号变化时，选择对应版本的文件。
2. 将 ZIP 完整解压到一个长期保留的目录。
3. 在解压结果中找到 `manifest.json`，它旁边应有 `dist` 文件夹，里面包含 `main.js` 和 `ui.html`。不要只复制 `manifest.json`。
4. 打开 Figma 设计文件，从插件菜单进入 **Plugins → Development → Import plugin from manifest…**（插件 → 开发 → 从 manifest 导入）。
5. 选择刚才的 `manifest.json`。
6. 从开发插件列表运行 **FigForge**。

看到 FigForge 窗口就表示插件已打开。安装后不要随意移动或删除解压目录；移动后需要重新导入 manifest。

如果你拿到的是源码而非安装包，请让维护者提供已打包插件。源码中的 `plugin/manifest.json` 也依赖旁边已生成的 `plugin/dist` 文件。

## 3. 准备要导出的界面

以“背包”和“商店”两个界面为例：

1. 将每个完整界面放在独立的 Frame 中，分别命名为“背包”和“商店”。
2. 第一次只选择“背包”最外层的 Frame，不要只选择里面的一段文字或一张图片。
3. 多选时，选择同一个父级下并列的 Frame、组件或 Group。不要同时选父节点和它里面的子节点。
4. 检查需要的图层是否可见，文字字体是否正常。

页面名称尽量简短且不重复，不要使用斜杠等路径符号，方便后续在 Unity 中识别。

## 4. 导出第一个 ZIP

1. 在 Figma 中选中“背包”Frame。
2. 在 FigForge 窗口查看图层树和预览。未更新时，点击顶部 **⟳** 重新扫描选择。
3. 顶部 **Export** 比例先保持 **1×**。
4. 底部“文件夹名”填写 `CommonUI`。它决定 ZIP 内部的根文件夹名，也会影响 Unity 的输出子目录。
5. 点击 **Add**，把当前选择加入导出列表。
6. 确认按钮显示 **导出 ZIP（1 个）**，然后点击它。
7. 等待导出完成，保存 `CommonUI.zip`。

**选中不等于加入导出列表，必须点 Add。** 换选其他节点不会自动清空已经加入的节点；重复添加同一节点不会重复计数。想重新选择一批内容时，点击 **Clear** 后再 Add。

导出的 ZIP 是给 Unity 用的数据包。不要把它当作 Figma 插件安装包，也不必解压后逐张拖图片到 Unity。

## 5. 一次导出多个界面

1. 点击 **Clear**，清空之前加入的节点。
2. 在 Figma 中同时选中同级的“背包”和“商店”。
3. 点击 **Add**。
4. 确认显示 **导出 ZIP（2 个）**。
5. 保持文件夹名 `CommonUI`，点击导出。

同一个 ZIP 会包含各界面的结构文件和共享图片，相同图片内容会在包内去重。Unity 可以从这一份 ZIP 生成两个页面预制体。

## 6. 常用选项怎么选

第一次可以保留默认设置。需要调整时参考下表：

| 选项 | 用途与注意事项 |
| --- | --- |
| Export：1×、2× 等 | 调整导出比例，会影响 PNG 分辨率和参考分辨率；先用 1× 跑通流程 |
| 命名清洗 | 默认保留原名，包括中文；需要统一清洗名称时再勾选 |
| 图层旁的 👁 | 控制是否导出该图层；排除容器会影响它的子层 |
| 图层旁的 ⊞ | 把容器及其内容合成一张 PNG；适合纯装饰，不适合需要分别操作的按钮或文字 |
| 文字旁的 P | 将文字导出为图片；外观固定，但 Unity 中不能再当普通文字修改内容 |
| 图层旁的 ↑ | 跳过这一层容器，将子节点提升到父级；不熟悉层级结构时先不要改 |
| Apply / Reset | 保存设置 / 恢复默认设置；不会替代 Add 或导出操作 |
| Fit、预览区 1×、＋、− | 调整预览显示，不是顶部的导出比例 |

图层列表的 All、Exported、Hidden 等按钮用于筛选查看，不等于把节点加入导出列表。

## 7. 怎么判断导出成功

- 已得到一个 ZIP 文件。
- 导出时节点数量与预期一致。
- 如果打开 ZIP 查看，可以看到以 `CommonUI` 为例的根文件夹、各页面的 `manifest.json`，以及有图片时的 `AltasImgs` 或 `RawImgs` 图片目录。

`AltasImgs` 是项目中的实际目录拼写，不需要手动改名。图片按导出的实际尺寸分类：宽高都小于 512 像素归入 `AltasImgs`，否则归入 `RawImgs`。这些目录不代表已经生成 Unity Sprite Atlas。

## 8. 常见问题

| 现象 | 先这样检查 |
| --- | --- |
| Add 灰色或提示选择错误 | 选择最外层 Frame、组件或 Group；多选必须同级 |
| 导出按钮显示 0 个 | 选好节点后点击 Add |
| 导出的页面比预期多 | 先 Clear，再只添加需要的页面 |
| 缺少图层 | 检查 Figma 可见性、插件中的 👁，以及父容器是否被排除或合并 |
| 导出卡住或下载失败 | 查看窗口错误提示；插件使用 cdnjs 加载 ZIP 打包库，需要能访问该服务 |
| 想在 Unity 改文字，却只能看到图片 | 检查文字是否开启了 P，或被合并进父容器 PNG；关闭后重新导出 |
| 界面出现 Download Frame / Download Page | 你使用的版本与本文不同；本文对应 Add 与“导出 ZIP”的操作流程 |

## 9. 下一步

将 `CommonUI.zip` 交给 Unity 使用者，继续阅读 [Unity 插件使用教程（小白版）](unity-beginner-guide.md)。同时说明设计中使用的字体，方便对方配置文字显示。
